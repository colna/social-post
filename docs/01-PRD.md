# social-post · 需求文档(PRD)

## 一句话

一个**可扩展的社媒帖子采集平台**:输入「平台 + 账户」,自动抓取该账户的帖子(封面图 + 完整文案),统一展示在平台表格中。首期实现 Instagram(INS)。

## 背景与目标

- 运营/增长同学需要盯若干社媒账户的内容产出,手工翻页低效。
- 需要一个统一后台:添加要监控的账户 → 一键抓取 → 表格里看每条帖子的封面、文案、点赞/评论、时间。
- **平台可扩展**:今天做 INS,明天加 TikTok / X / 小红书,只需实现一个平台适配器,不改上层。

## 用户与场景

| 角色 | 场景 |
|------|------|
| 运营 | 添加一个 IG 账户 → 点「抓取」→ 表格里看这个号最近 N 条帖子的封面+文案 |
| 运营 | 在平台列表切换不同平台,查看各自账户与帖子 |
| 运营 | 对某账户「重新抓取」,更新到最新帖子 |

## 功能范围(首期)

### P0(必须)
1. **平台管理**:内置平台列表(instagram 已启用),前端可见、可切换。平台可扩展(后端加适配器 + 库里加一行)。
2. **账户管理**:某平台下增删查账户(handle/username);展示账户画像(展示名、头像、bio、粉丝/关注/帖子数、是否认证/私密)。
3. **帖子抓取**:对某账户触发抓取 → 后端调用爬虫服务 → 落库。抓取封面图 URL + 帖子完整文案 + 类型(图文/视频/轮播/reel)+ 点赞/评论数 + 发布时间 + 原始 shortcode/链接。
4. **帖子表格展示**:按账户查看帖子列表,表格含封面缩略图、文案、类型、点赞、评论、发布时间、原帖链接;支持分页。

### P1(后续)
- 定时自动抓取(cron)。
- 帖子去重/增量抓取(已抓过的 shortcode 跳过或更新)。
- 多平台聚合视图。
- 抓取任务状态/进度可视化。

### 非目标(明确不做)
- 不做发帖/互动(纯只读采集)。
- 不做内容二次分发。
- 不绕过平台强反爬对抗(命中风控由运营换 cookie/代理解决,不做黑产级对抗)。

## 关键约束

- **合规**:仅抓公开可见内容;需要登录态时由运营提供自己的账号 cookie(env 注入),平台不内置账号池。
- **INS 抓取口径**:直接请求 Instagram 私有 web API `web_profile_info`(带 `x-ig-app-id` + 登录 cookie),一次返回用户信息 + 帖子列表(含封面 `display_url` + 完整文案 `caption`),**不依赖浏览器 DOM 滚动**。参考 sitin-next `app-ins-scripts/getProfilePostImage.js` 的字段口径。
- **部署**:前端 + NestJS 后端 → Vercel;Python 爬虫服务(Scrapling)→ 独立容器部署(Railway/Render/Fly),不上 Vercel Serverless。

## 验收标准

- [ ] 前端能添加一个公开 IG 账户,点「抓取」后表格出现该账户的帖子。
- [ ] 每条帖子有封面缩略图、完整文案、类型、点赞/评论、发布时间、原帖链接。
- [ ] 平台层可扩展:新增一个平台适配器 + 数据库一行即可在前端出现,无需改上层通用逻辑。
- [ ] 数据落 Neon Postgres,刷新页面/重启后仍在。
- [ ] 三端(web/server/crawler)本地可跑通;web + server 有 Vercel 部署配置,crawler 有 Dockerfile + 部署说明。

## 度量

- 单账户抓取成功率、单次抓取帖子数、抓取耗时;命中风控(429/challenge)次数。
