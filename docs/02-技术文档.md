# social-post · 技术文档

## 总体架构

```
┌────────────────┐        HTTP/JSON        ┌────────────────────┐        HTTP/JSON        ┌──────────────────────┐
│  apps/web       │  ───────────────────▶  │  apps/server        │  ───────────────────▶  │  services/crawler     │
│  umi + antd v6  │  ◀───────────────────  │  NestJS (REST API)  │  ◀───────────────────  │  FastAPI + Scrapling  │
│  + tailwind     │                        │  Prisma → Neon      │                        │  (Python, 独立部署)    │
│  (Vercel)       │                        │  (Vercel)           │                        │  (Railway/Render)     │
└────────────────┘                        └─────────┬──────────┘                        └──────────┬───────────┘
                                                     │ Prisma                                        │ Instagram
                                                     ▼                                               ▼ web_profile_info API
                                            ┌──────────────────┐                          (+ 未来其它平台 crawler)
                                            │  Neon Postgres    │
                                            └──────────────────┘
```

- **web**:纯前端,只跟 server 说话。
- **server**:业务/编排中枢。管理平台、账户、帖子;触发抓取时调用 crawler 服务,拿到结果写入 Neon。**server 不直接爬**,爬取全部下沉到 crawler。
- **crawler**:唯一接触目标平台的服务。用 Scrapling 请求 Instagram `web_profile_info`,解析成统一 schema 返回。平台可插拔。

> 为什么 crawler 独立成 Python 服务:Scrapling 是 Python 且可选启用 camoufox 浏览器做反爬,Vercel Serverless 跑不了;拆出来独立容器部署,server 只做 HTTP 调用,职责清晰、可独立扩缩容。

## 数据模型(Prisma / Postgres)

```prisma
model Platform {
  id        String   @id @default(cuid())
  key       String   @unique          // "instagram"
  name      String                    // "Instagram"
  enabled   Boolean  @default(true)
  createdAt DateTime @default(now())
  accounts  Account[]
}

model Account {
  id             String   @id @default(cuid())
  platformKey    String
  handle         String                 // username,如 "nasa"
  displayName    String?
  avatarUrl      String?
  bio            String?
  followerCount  Int?
  followingCount Int?
  mediaCount     Int?
  isVerified     Boolean  @default(false)
  isPrivate      Boolean  @default(false)
  externalUrl    String?
  externalId     String?                // 平台侧用户 id
  lastCrawledAt  DateTime?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
  platform       Platform @relation(fields: [platformKey], references: [key])
  posts          Post[]
  @@unique([platformKey, handle])
}

model Post {
  id           String   @id @default(cuid())
  accountId    String
  platformKey  String
  shortcode    String                  // 平台侧帖子唯一码
  url          String
  type         String                  // image | video | carousel | reel
  coverUrl     String                  // 封面图
  caption      String?  @db.Text       // 完整文案
  likeCount    Int?
  commentCount Int?
  takenAt      DateTime?               // 发布时间
  raw          Json?                   // 原始节点,便于后续扩展
  createdAt    DateTime @default(now())
  account      Account  @relation(fields: [accountId], references: [id], onDelete: Cascade)
  @@unique([platformKey, shortcode])
  @@index([accountId])
}
```

- `@@unique([platformKey, shortcode])` 实现帖子去重(增量抓取用 upsert)。
- `raw` 存原始 JSON,平台差异字段不丢,前端/后续分析可用。

## 平台可扩展性设计

**crawler 侧**:每个平台一个 `PlatformCrawler`,实现统一接口:

```python
class PlatformCrawler(Protocol):
    key: str
    async def fetch_profile(self, handle: str, opts: CrawlOptions) -> ProfileResult: ...
```

`ProfileResult` 是跨平台统一结构(account 画像 + posts 列表)。注册表 `CRAWLERS: dict[str, PlatformCrawler]`,API 按 `platform` 参数派发。新增平台 = 新增一个实现 + 注册一行。

**server 侧**:`CrawlerClient.crawl(platform, handle, opts)` 只透传 platform,不含平台特判;落库逻辑对所有平台通用(统一 schema)。新增平台无需改 server 业务代码,只需库里 `Platform` 加一行 + crawler 加适配器。

## INS 抓取技术方案

核心:Instagram 私有 web API

```
GET https://www.instagram.com/api/v1/users/web_profile_info/?username=<handle>
Headers:
  x-ig-app-id: 936619743392459        # IG web 前端固定 app id
  Cookie: <运营账号登录 cookie>          # env 注入,登录态,规避未登录风控
  User-Agent: <桌面 Chrome UA>
```

响应 `data.user`:
- 画像:`username / full_name / biography / profile_pic_url_hd / edge_followed_by.count / edge_follow.count / edge_owner_to_timeline_media.count / is_verified / is_private / external_url / id`
- 帖子:`edge_owner_to_timeline_media.edges[].node`:
  - `shortcode`、`display_url`(封面)、`is_video`、`__typename`(`GraphImage`/`GraphVideo`/`GraphSidecar`)
  - `edge_media_to_caption.edges[0].node.text`(**完整文案**)
  - `edge_liked_by.count`(点赞)、`edge_media_to_comment.count`(评论)
  - `taken_at_timestamp`(发布时间)
  - `edge_sidecar_to_children`(轮播子项)

**用 Scrapling 而非裸 httpx**:Scrapling 的 `Fetcher`(带浏览器级 TLS 指纹 impersonation)直接 GET 该 JSON 端点,规避 TLS 层面反爬;命中 challenge 时可降级到 `StealthyFetcher`(camoufox 浏览器)。首期先用 `Fetcher` + cookie,足够公开号。

类型映射:`__typename == GraphSidecar` → carousel;`is_video` 且 URL 含 `/reel/` → reel;`is_video` → video;否则 image。

## 各端技术选型

### web(apps/web)
- **umi 4** + React 18。
- **antd v6**(`antd@6`)。通过 umi 内置 antd 插件或手动引入。
- **tailwindcss v3**。⚠️ tailwind preflight 会重置 antd 基础样式 → 关闭 preflight(`corePlugins.preflight = false`),只用 tailwind 的原子类做布局微调,组件样式交给 antd。
- 数据请求:umi `request` / `useRequest`(ahooks)。
- 环境变量 `UMI_APP_API_BASE` 指向 server。

### server(apps/server)
- **NestJS 10** + Fastify/Express adapter(用默认 Express,Vercel 兼容好)。
- **Prisma** ORM → Neon Postgres。
- 模块:`PlatformModule` / `AccountModule` / `PostModule` / `CrawlerModule`(HTTP client)/ `PrismaModule`。
- REST 风格,`/api/*` 前缀。
- 测试:Jest(NestJS 默认)或 Vitest。选 **Vitest**(与前端一致、快)。
- 环境变量:`DATABASE_URL`(Neon)、`CRAWLER_BASE_URL`、`CRAWLER_TOKEN`。

### crawler(services/crawler)
- **FastAPI** + uvicorn。
- **Scrapling** 抓取。
- 接口:`POST /crawl/{platform}` body `{handle, maxPosts, cookie?}` → 统一 `ProfileResult` JSON。
- 鉴权:`Authorization: Bearer <CRAWLER_TOKEN>`(server↔crawler 之间)。
- 测试:pytest(用本地 fixture JSON mock IG 响应,不打真实 IG)。
- 环境变量:`IG_COOKIE`(默认 cookie,可被请求覆盖)、`CRAWLER_TOKEN`、`SCRAPLING_MODE`(fetch|stealth)。
- Docker:`python:3.11-slim` + scrapling 依赖。

## API 契约(server ↔ web)

| Method | Path | 说明 |
|--------|------|------|
| GET | `/api/platforms` | 平台列表 |
| GET | `/api/accounts?platform=instagram` | 账户列表 |
| POST | `/api/accounts` `{platform, handle}` | 新增账户 |
| DELETE | `/api/accounts/:id` | 删除账户 |
| POST | `/api/accounts/:id/crawl` `{maxPosts?}` | 触发抓取(同步:调 crawler → 落库 → 返回账户+新增数) |
| GET | `/api/accounts/:id/posts?page=&pageSize=` | 帖子分页 |

## API 契约(server ↔ crawler)

```
POST {CRAWLER_BASE_URL}/crawl/instagram
Authorization: Bearer <CRAWLER_TOKEN>
Body: { "handle": "nasa", "maxPosts": 30, "cookie": "<可选覆盖>" }
Resp: {
  "account": { "handle","displayName","avatarUrl","bio","followerCount","followingCount","mediaCount","isVerified","isPrivate","externalUrl","externalId" },
  "posts": [ { "shortcode","url","type","coverUrl","caption","likeCount","commentCount","takenAt","raw" } ],
  "fetchedAt": "ISO"
}
```

## 安全

- cookie / token 全走环境变量,不进仓库(提供 `.env.example`)。
- crawler 只接受带 `CRAWLER_TOKEN` 的请求。
- 封面图 URL 是 IG CDN 直链(有防盗链/时效),前端直接 `<img>` 展示;必要时 server 侧加图片代理(P1)。

## 部署拓扑

- **web** → Vercel(framework: umi,build `pnpm --filter web build`,root `apps/web`)。
- **server** → Vercel(Node Serverless,`api/index.ts` 引导 Nest app;root `apps/server`)。Prisma 需 `postinstall: prisma generate`,build 时 `prisma migrate deploy`。
- **crawler** → Railway/Render(Dockerfile);给 server 配 `CRAWLER_BASE_URL`。
- Neon → 直接用其 connection string 作 `DATABASE_URL`。
