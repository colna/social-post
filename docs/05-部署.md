# social-post · 部署指南

三个可独立部署单元:**web(Vercel)**、**server(Vercel)**、**crawler(Railway/Render 容器)**、DB 用 **Neon**。

## 0. 准备 Neon 数据库

1. https://neon.tech 建项目,拿到 connection string(形如 `postgresql://user:pwd@ep-xxx.neon.tech/db?sslmode=require`)。
2. 作为 `DATABASE_URL` 提供给 server。建表在 server 首次部署 build 时自动执行(`prisma migrate deploy`,迁移文件已在 `apps/server/prisma/migrations/`)。
3. 建表后跑一次 seed 插入平台:本地 `DATABASE_URL=... pnpm --filter server prisma:seed`(或在 Neon SQL 控制台手动插一行 `Platform`:key=instagram)。

## 1. 部署 crawler(Railway 或 Render)

爬虫是 Python + Scrapling,**不能上 Vercel Serverless**,用容器平台。

### Railway
1. New Project → Deploy from GitHub → 选本仓库。
2. Root Directory 设 `services/crawler`(Railway 自动识别 Dockerfile)。
3. Variables:`CRAWLER_TOKEN`(自定义强密码)、`IG_COOKIE`(运营 IG 登录 cookie 整段)、`SCRAPLING_MODE=fetch`。
4. 部署后拿到公网 URL(如 `https://xxx.up.railway.app`),`GET /health` 应返回 `{"status":"ok"}`。

### Render(Blueprint)
1. New → Blueprint,指向仓库,Render 读 `services/crawler/render.yaml`。
2. 面板填 `CRAWLER_TOKEN`、`IG_COOKIE`。
3. healthCheck 路径已配 `/health`。

> **IG_COOKIE 怎么拿**:浏览器登录 instagram.com → DevTools → Network → 任一 `www.instagram.com` 请求 → 复制 Request Headers 里的整段 `cookie`(含 `sessionid` 等)。cookie 会过期,失效后在 crawler 平台更新该变量即可。

## 2. 部署 server(Vercel)

1. Vercel New Project → Import 本仓库。
2. **Root Directory** 设 `apps/server`。
3. Vercel 读 `apps/server/vercel.json`:
   - buildCommand:`prisma generate && nest build && mkdir -p public`(`public/` 仅为满足 Vercel 输出目录检查)
   - 所有请求 rewrite 到 serverless 函数 `api/index.js`(纯 JS 薄壳 → require `dist/bootstrap.js`,内部 Nest 带 `/api` 前缀)。
   - **为什么这样**:NestJS 构造函数注入依赖 tsc 的 `emitDecoratorMetadata`,而 Vercel 的 `api/` 默认用 esbuild 编译会丢这份元数据 → DI 崩。故先 `nest build`(tsc)出带元数据的 `dist/`,函数入口只是薄壳 require 它。
4. Environment Variables:
   - `DATABASE_URL` = Neon 串(build 时 `prisma generate` 需要它已定义)
   - `CRAWLER_BASE_URL` = 第 1 步 crawler 的公网 URL
   - `CRAWLER_TOKEN` = 与 crawler 一致
5. **首次部署前/后手动建表**(migrate 不在 build 里跑,避免 build 强依赖连库):
   ```bash
   # 本机,用 Neon 串跑一次即可(幂等)
   DATABASE_URL='<neon 串>' pnpm --filter server prisma migrate deploy
   DATABASE_URL='<neon 串>' pnpm --filter server prisma:seed   # 插入 instagram 平台
   ```
6. 部署后 `GET https://<server>.vercel.app/api/platforms` 应返回平台数组。

> Prisma 已配 `binaryTargets = ["native","rhel-openssl-3.0.x"]` 适配 Vercel 运行时。

## 3. 部署 web(Vercel)

1. Vercel New Project → 同仓库(第二个 project)。
2. **Root Directory** 设 `apps/web`。
3. Vercel 读 `apps/web/vercel.json`:`umi build` → `dist`,SPA rewrite 到 `index.html`。
4. Environment Variables:`UMI_APP_API_BASE` = `https://<server>.vercel.app/api`。
5. 部署后打开即用。

## 4. 环境变量总表

| 变量 | 用于 | 说明 |
|------|------|------|
| `DATABASE_URL` | server | Neon Postgres 连接串 |
| `CRAWLER_BASE_URL` | server | crawler 公网地址 |
| `CRAWLER_TOKEN` | server + crawler | 两边必须一致的共享密钥 |
| `IG_COOKIE` | crawler | 运营 IG 登录 cookie |
| `SCRAPLING_MODE` | crawler | `fetch`(默认)/ `stealth`(浏览器,重) |
| `UMI_APP_API_BASE` | web | 指向 server 的 `/api` |

## 5. 本地联调(全链路)

```bash
cp .env.example .env   # 填 DATABASE_URL / IG_COOKIE / CRAWLER_TOKEN
pnpm install

# crawler
cd services/crawler && python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && CRAWLER_TOKEN=xxx IG_COOKIE='...' uvicorn app.main:app --port 8000

# server(另开终端,项目根)
pnpm --filter server prisma migrate deploy && pnpm --filter server prisma:seed
CRAWLER_BASE_URL=http://localhost:8000 CRAWLER_TOKEN=xxx pnpm server:dev

# web(另开终端)
pnpm web:dev   # 打开 http://localhost:8000(umi) → 加账户 → 抓取
```

> 本机系统 Python 是 3.9,Scrapling 建议 3.11。本地无 3.11 时,crawler 用 Docker 跑:
> `cd services/crawler && docker build -t sp-crawler . && docker run -p 8000:8000 -e CRAWLER_TOKEN=xxx -e IG_COOKIE='...' sp-crawler`
